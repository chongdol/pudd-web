ใช้ให้ปลอดภัย

  • งานสำคัญ (ลบข้อมูล ย้ายระบบ นโยบาย เงิน) — อ่านคำแปลก่อนกดส่งทุกครั้ง
  • เวลาและตัวเลข — พูดเป็นตัวเลขชัด ๆ เช่น “23:00” แทน “ห้าทุ่ม”
  • ประโยคที่มี “ห้าม / ไม่ / ต้องไม่ / กัน…” — ตรวจว่าความหมายไม่กลับด้าน
  • พูดยาวมากให้แบ่งเป็นช่วง: ตัวแปลในเครื่องรับได้ดีทีละช่วงสั้น ๆ ถ้าส่งข้อความไทยยาวเกินราว 700 ตัวอักษรรวดเดียว คำแปลท้าย ๆ จะหายไป (ได้อังกฤษกลับมาแค่ ~905–950 ตัวอักษร โดยไม่มีข้อความเตือน) · ตัวเลขในหน้านี้ทั้งหมดมาจากการแปลทีละช่วงที่ครบแล้ว
  • ชื่อไฟล์ ชื่อฟังก์ชัน ชื่อคำสั่ง — พูดเป็นภาษาอังกฤษตามจริง · ชื่อเฉพาะภาษาไทยจะถูกแปลไปด้วย ถ้าต้องการชื่อเดิมให้ปิดโหมดแปลชั่วคราว (ข้อนี้ไม่ได้ทดสอบแยก)

วิธีวัด

  1. เขียนคำสั่งงานภาษาไทยขึ้นใหม่ 18 ข้อความ 5 กลุ่มความยาว (สั่งแก้โค้ด อธิบายบั๊ก ร่างอีเมล สรุปงาน รีวิวโค้ด สเปก แผนย้ายระบบ เอกสารนโยบาย) ชื่อในข้อความเป็นของสมมติทั้งหมด
  2. แปลด้วยตัวแปลจริงของ PUDD v1.0.70 (PUDD --translate = Translation.framework ของ macOS ในเครื่อง) ทีละช่วง ไม่เกิน ~200 ตัวอักษร · แปลซ้ำได้ผลเหมือนเดิมทุกช่วง
  3. Claude: claude -p --model sonnet (Sonnet 5) ไม่มีเครื่องมือ system prompt สั้นคงที่ (คำขอเปล่า 322 โทเค็น) รวมข้อความในกลุ่มความยาวเดียวกันต่อการเรียก — 11 การเรียก · การวัดก่อนหน้าวันเดียวกัน (ข้อความจริง 955 ตัวอักษร) ได้ 822 → 256 โทเค็น
  4. Codex: codex exec --ignore-user-config --ephemeral -s read-only --json ในโฟลเดอร์ว่าง สั่งให้ตอบแค่ OK แล้วอ่าน input_tokens จริง · โทเค็นของข้อความ = คำขอที่มีข้อความ − คำขอเปล่า (17,676) — 62 การเรียก (สำเร็จ 54) · รุ่น gpt-6-luna, gpt-6-sol, gpt-5.5
  5. ตรวจไขว้: ข้อความยาวสุดได้โทเค็นเท่ากันทุกรุ่นของ Codex — gpt-6-luna: ไทย 1,216 / อังกฤษ 914 · gpt-6-sol: ไทย 1,216 / อังกฤษ 914 · gpt-5.5: ไทย 1,216 / อังกฤษ 914
  6. สัญญาณรบกวน: วัดซ้ำ 3 ข้อความเต็มได้เท่ากันทุกโทเค็น แต่ 3 จาก 36 การเรียกรอบแรกอ่านได้สูงเกิน +53 โทเค็น และคำขอเปล่า 1 ใน 3 ครั้งได้ 21,901 (สูงกว่าปกติ 4,225) โดยไม่รู้สาเหตุ — วัดซ้ำแล้วใช้ค่าต่ำสุดของแต่ละรายการ
